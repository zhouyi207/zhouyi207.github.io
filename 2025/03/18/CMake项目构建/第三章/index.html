1. CMake 程序

CMake 程序根据程序名，可以分为以下两种类型：

  1. 名为 CMakeLists.txt 的文件
  2. 拓展名为 .cmake 的程序

其中 CMakeLists.txt 文件用于组织构建项目源程序的目录结构。拓展名为 .cmake 的程序又分为 脚本程序 和 模块程序 两种类型。

1. CMakeLists.txt

当 CMake 被用于构建时，处理源程序的入口就是项目顶层目录下的 CMakeLists.txt 文件，这与 Makefile 相似。在 CMakeLists.txt 中，可能还会通过 add_subdirectory 命令将一些子目录追加到构建目录中，这要求子目录中也又一个 CMakeLists.txt

2. 脚本程序.cmake

指定 -P 参数运行 CMake 命令行工具可以执行脚本类型的 CMake 程序，这种 CMake 程序不会配置生成任何构建系统，因此一些与构建相关的 CMake 命令是不允许出现在脚本中的。

3. 模块程序.cmake

CMake 的目录程序 和 脚本程序均可以通过 include 等命令引用 CMake 模块程序。CMake 提供了很多预制模块供用户使用，CMake 模块是一种主要的代码复用单元。

2. 注释

3. 命令调用 和 命令参数

1. 命令调用

CMake 的命令调用类似于其他编程语言中的函数调用，先书写命令名称，其后跟括号括起来的命令参数。CMake 的命令名称不区分大小写，一般使用小写。

如果有多个参数，在 CMake 中应当使用空格或换行符等空白符将它们分隔开，空格仅用于分割参数，并不是参数内容，因此最终输出的消息是 abc

2. 命令参数

命令参数在命令调用的括号中书写，命令参数一共有以下三种类型：

  1. 引号参数
  2. 非引号参数
  3. 括号参数

1. 引号参数

引号参数是用引号包裹的参数，CMake 规定它必须使用双引号，引号参数会作为一个整体传递给命令，引号中间的空白符都会作为这个整体的一部分，也就是说引号参数中不仅能包含空格，也能包含换行符。如果不需要换行符，可以通过在代码行末的反斜杠 \ 避免。

2. 非引号参数

非引号参数自然指未被引号包裹的参数，这种参数中不能包含任何空白符，也不能包含圆括号，#符号，双引号和反斜杠，除非经过转义。非引号参数也支持变量的引用和转义字符。

非引号参数在被传递前，会被当作 CMake 列表来处理，而列表中的每一个元素都会作为一个单独的参数传递给命令。

3. 变量引用

变量引用类似于很多编程语言提供的字符串插值语法，可以在参数内容中插入一个变量的值。CMake 变量引用形式为 ${变量名}，可以用在引号参数和非引号参数中。CMake 会将其替换为对应变量的值。若变量名未定义，CMake 不会报错，而是将其替换未空字符串。另外，变量引用还支持嵌套的递归引用。

4. 转义字符

一个反斜杠和紧跟其后的一个字符构成一个转义字符，它基本分为以下四种情况：

  1. 如果其后跟随的字符不是字母，数字或分号，转义的结果就是该字符本身
  2. “\t”, “\r” 和 “\n” 分别会转义成 Tab，回车，换行
  3. “;” 的转义又分为以下情况：
    1. 如果它被用于变量引用或非引用参数中，则转义为分号 “;”。但在非引号参数，转义后分号不用于分隔列表元素，即其前后相邻文本包括分号本身会作为一个整体。
    2. 其他情况，则不进行转义，即反斜杠保留，仍为 “;”
  4. 其他情况则是错误的转义

3. 变量

同大多数编程语言一样，CMake 中的变量也是存储数据的基本单元，但 CMake 变量其数据类型总是文本型的，只不过在使用时，文本型的变量可能被一些命令解释成数值，列表等，以实现更加丰富的功能。

变量的分类

CMake 有三种变量分类：

  1. 普通变量
  2. 缓存变量
  3. 环境变量

普通变量具有特定的作用域，环境变量具有全局作用域。缓存变量会被持久化到缓存文件 CMakeCache.txt。CMake 程序每次被执行时，都会从被持久化的缓存文件中读取缓存变量的值，这可以用于避免每次都执行一些耗时的过程来获得数据。

例如：当使用 CMake 构建项目时，它第一次配置时会检测编译器路径，然后将其作为缓存变量持久化，这样可以避免每次执行都重新进行检测。缓存变量主要用于构建过程， cmake -P 执行脚本程序时不会对缓存变量进行修改，缓存变量具有全局的作用域。

变量的作用域

普通变量会绑定到某个作用域中，作用域分为两种：

  1. 函数作用域，在用户自定义的函数命令中会有一个独立的作用域。默认情况下，函数内定义的变量只在函数内部或函数中调用的其他函数可见。
  2. 目录作用域，对于 CMake 的目录程序而言，每一个目录层级都有它的一个作用域。子目录的程序被执行前，会先将父目录作用域中的所有变量复制一份到子目录的作用域中。因此，子目录的程序可以访问但是无法修改父目录作用域中的变量。对于 CMake 脚本程序而言，目录的作用域相当于只有一层。

保留标识符

CMake 会将以下 3 种形式的名称作为保留标识符，自定义变量或命令时应当注意避开它们：

  1. 以 CMAKE_ 开头的名称（不区分大小写）
  2. 以 _CMAKE_ 开头的名称 （不区分大小写）
  3. 下划线 _ 加上 CMake 中任意一个预定义命令的名称，如 _message

1. 预定义变量

CMake 中有很多预定义的普通变量和环境变量，它们一般以 CMAKE_ 开头，即属于保留标识符。预定义变量往往与系统配置，运行环境，构建行为，编译工具链，编程语言等信息相关。

  1. CMAKE_AGRC 表示 CMake 脚本程序在被 cmake -P 命令行调用执行时，命令行传递的参数个数。
  2. CMAKE_ARGV0，CMAKE_ARGV1 表示 CMake 脚本程序在被命令行调用执行时，命令行传递的第一个，第二个参数，依次类推。
  3. CMAKE_COMMAND 表示 CMake 命令行程序所在的路径
  4. CMAKE_HOST_SYSTEM_NAME 表示宿主机操作系统（运行 CMake 的操作系统）名称。
  5. CMAKE_SYSTEM_NAME 表示 CMake 构建的目标操作系统名称，默认与宿主机操作系统一致，一般用于交叉编译时，由开发者显示设置。
  6. CMAKE_CURRENT_LIST_FILE 表示当前运行中的 CMake 程序对应文件的绝对路径。
  7. CMAKE_CURRENT_LIST_DIR 表示当前运行中的 CMake 程序所在目录的绝对路径。
  8. MSVC 表示在构建时 CMake 当前使用的编译器是否为 MSVC
  9. WIN32 表示当前目标操作系统是否为 Windows
  10. APPLE 表示当前目标操作系统是否为苹果操作系统
  11. UNIX 表示当前目标操作系统是否为 UNIX 或类 UNIX 平台（包括 Linux，苹果操作系统及 Cygwin 平台）

VERSION_LESS_EQUAL 判断第一个版本号是否小于或等于第二个版本号 if("1.2.3" VERSION_LESS_EQUAL "1.2.3")
VERSION_GREATER_EQUAL 判断第一个版本号是否大于或等于第二个版本号 if("1.2.4" VERSION_GREATER_EQUAL "1.2.3")
列表元素判断 IN_LIST 检查一个元素是否存在于一个列表中，列表通常是以分号分隔的字符串形式表示 set(MY_LIST "apple;banana;cherry"); if("banana" IN_LIST MY_LIST)

4. 参数的设计和解析

在 CMake 中，命令的设计有一些约定俗成的规范，而且 CMake 也提供了一个简单实用的命令 cmake_parse_arguments，可以按照这个规范来解析用户传递的命令参数。

参数的设计规范

CMake 的命令参数主要由两部分构成：一部分是用户提供的参数值；另一部分则是一些关键字，用于构成参数的结构。这些关键字的名称往往由全大写的字母组成。另外关键字可以分为如下三种类型：

  1. 开关选项关键字：调用者可以通过指定该参数来启用某个选项，开关选项参数可以理解为一种表示布尔值的参数。
  2. 单值参数关键字：它的后面会且仅会跟随一个参数值，相当于键值映射，一个关键字对应一个实际参数值
  3. 多值参数关键字：它的后面可以跟随多个参数值，相当于一个接受列表的参数。

cmake_parse_arguments 的通用形式

cmake_parse_arguments 命令正是用于解析符合这个规范的参数。该命令由两种形式：一种是在函数或宏中均可使用的通用形式，但它无法解析一些包含特殊符号的单值参数；另一种形式则不存在这一缺陷，但是只支持在函数中使用。

5. 宏和函数的区别

执行上下文和作用域

宏会与调用上下文共享作用域，而函数有独立的作用域。

定义外部可见的变量

在宏中可以直接通过 set 命令最简单的形式定义宏之外可以访问的变量，而在函数内就必须为 set 命令指定 PARENT_SCOPE 参数。

CMake 命令没有返回值这一概念，定义外部可见的变量其实是 CMake 函数 “返回值” 的形式。CMake 的 return 命令并不负责返回值，仅用于结束当前执行上下文。

预定义变量

函数体中可以通过访问 CMake 预定义的变量，获取关于当前执行中的函数的一些信息。

  • CMAKE_CURRENT_FUNCTION: 值为当前函数名称
  • CMAKE_CURRENT_FUNCTION_LIST_DIR：值为定义当前函数的 CMake 程序文件所在的目录
  • CMAKE_CURRENT_FUNCTION_LIST_FILE：值为定义当前函数的 CMake 程序文件的完整路径
  • CMAKE_CURRENT_FUNCTION_LIST_LINE：值为当前函数在 CMake 程序文件中定义时对应的程序代码行行号

参数访问

宏和函数均可通过引用形式参数，参数列表或索引等方式来访问实际参数。在函数中，包括形式参数，ARGC，ARGV，ARGN 等都是真正的 CMake 变量，且定义在当前函数的作用域内。

CMake 在展开宏时，会对宏的命令序列进行预处理，对引用这些符号的地方直接进行文本替换。这会带来一个问题：在宏中，不能直接将这些访问参数的符号作为变量条件用于条件语法，也不能利用变量嵌套引用语法访问这些符号。
