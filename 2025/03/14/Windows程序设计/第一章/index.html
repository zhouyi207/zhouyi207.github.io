LRESULT：L 的意思是 LONG，LRESULT 是 LONG_PTR 的别名，LONG_PTR 又是 long 的别名，PTR 是指针的意思，但是在 Win32 中，一般以 P 开头的才是代表指针类型，这里的PTR的意思是：通过使用LONG_PTR这种与指针大小相同的整数类型，可以方便地处理内存地址等情况，并且在代码中能够以统一的整数运算方式来操作这些类似于指针的值。

CALLBACK 和 WINAPI

有两种调用约定，一种是 __stdcall，另一种是 __cdecl 。被普通应用程序调用的函数调用约定为 __cdecl，而被操作系统调用的函数调用约定为 __stdcall。这两种调用约定的区别主要是函数形参内存的回收方式不同。

在应用程序中编写的函数既可以被应用程序调用，也可以被 Windows 操作系统调用，如果需要被系统调用，则应该添加 __stdcall 来进行修饰。

CALLBACK 和 WINAPI 与函数的调用约定有关，由 CALLBACK 和 WINAPI 修饰的函数又称为回调函数。回调函数是被操作系统调用的，较为常见的有窗口过程函数，线程函数等，所以应该在这些函数在声明的时候应该用 CALLBACK 和 WINAPI 来修饰。Windows API 函数是操作系统提供给应用程序调用的函数，而回调函数是应用程序提供给操作系统调用的函数；

__cdecl 调用约定 main 函数比 __stdcal 调用约定 main 函数在调用其他函数的时候多了一行 add esp, ？，这行代码用于回收形参的内存。而在main函数调用的函数里面，__cdecl 直接使用 ret 返回，而 __stdcal 使用 ret ? 返回。由此可见主要的区别在于： __cdecl 由主调函数回收形参的内存，而 __stdcal 由被调函数回收形参的内存。(这里的？指的是形参的字节大小，如果是两个整型则是8)

WndProc

WndProc 为窗口过程函数名，可以自主命名。窗口过程函数必须在定义好的窗口类对象中，赋值给窗口类对象 WNDCLASS 的 lpfnWndProc 成员。当操作系统类注册窗口类对象的时候，操作系统就会知道该类型的窗口的消息应当调用哪个窗口过程函数；

HWND 和 UINT

HWND 是句柄，UINT 是消息结构体对象

WPARAM 和 LPARAM

WPARAM 是一个32位的无符号整型数据，LPARAM 是一个32位的长整型数据，这两数据的含义和数值会根据消息的不同而不同。

3. Windows 应用程序的入口函数

Windows 图形界面的应用程序的入口函数名必须为 WinMain，而且调用约定必须为 __stdcall （入口函数是由操作系统来调用的），因此该函数的4个参数也是由操作系统来赋值的。

HINSTANCE hInstance

该参数为应用程序实例句柄，当用户运行应用程序时，就会创建一个应用程序实例句柄，该句柄的本质是进程句柄，一个应用程序运行时，操作系统就会创建一个进程和一个主线程（线程函数为 WinMain）。进程创建的同时会返回一个进程句柄，操作系统以及其他应用程序可以通过进程句柄来管理进程，例如：终止进程的执行或通过管道向进程传递数据。

HINSTANCE hPrevInstance

该参数为前一个实例句柄，一个应用程序可以运行很多次，每次都会创建一个实例句柄。

PSTR szCmdLine

该参数为命令行参数，当通过命令方式启动一个应用程序时，可以在命令中输入相应的参数。

6. 定义消息结构体对象

MSG 的定义在 WINUSER.H 文件中的定义如下：

  1. HWND hwnd：发生消息的窗口句柄，Windows 图像界面的应用程序是靠消息驱动的，单击鼠标，按键盘上的按键，选择应用程序的菜单等动作都会被操作系统接收到，并根据当前执行的操作给 MSG 类型对象的相应成员赋值；操作系统会将当前获得焦点的窗口句柄的值赋给消息对象的 hWnd。在操作系统向窗口的消息队列投递消息时，会将当前的 MSG 消息对象投递给窗口句柄与 MSG 消息对象 hWnd 的值相等的那个窗口的消息队列，进而执行相应的窗口过程函数。即在哪个窗口发送的消息传递给哪个窗口的消息队列的过程函数，通过 hWnd 值来传递
  2. UINT message：Windows 操作系统给每个消息指定一个编号，即 ID，该编号称为消息代码，在 WinUser.H 文件中，里面有很多以 WM_ 开头的常量定义，用户也可以自己定义消息，但一定要注意不能和系统定义的消息冲突，为了保证不与系统冲突，在WinUser.H 文件中定义了一个常量 #define WM_USER 0x0400，用户定义消息时，可以如下定义避免冲突 #define WM_MYMESSAGE1 WM_USER + 1
  3. WPARAM wParam 和 LPARAM lParam：消息发生时的参数，随着消息的不同而变化，如：当发生 WM_LBUTTONDOWN 消息，即鼠标左键按下消息时，wParam 表示不同虚拟键是否按下，如果取值为 MK_CONTROL，则表示按鼠标左键的同时还按了 Ctrl 键；lParam 的低16位表示鼠标左键按下时的 x 坐标，高16为表示y坐标（以像素为单位）
  4. DWORD time：消息发生的事件
  5. POINT pt：消息发生时光标的位置，分为 x，y 坐标

两个函数的函数原型如下：

23. 窗口过程函数

窗口过程函数即应用程序提供给操作系统的回调函数，用于操作系统处理应用程序的消息，窗口过程函数有 4 个成员参数，这 4 个成员参数恰好对应着 MSG 结构体的前 4 个成员，其分别指定了发生消息的窗口的窗口句柄，消息代码，wParam 和 lParam。

其流程为：GetMessage 函数从窗口消息队列中取出消息，然后调用 DispatchMessage 将消息分派给操作系统，操作系统将 MSG 结构体类型对象的前 4 个成员传递给窗口过程函数，窗口过程函数使用 switch 根据消息代码来判断消息的类型进而处理消息，而参数 wParam 和 lParam 中包含了需要消息处理的数据。

(1) WM_CREATE 消息

窗口创建成功，在还没有显示之前就会响应 WM_CREATE 消息，WM_CREATE 消息的定义为 #define WM_CREATE 0x0001

(2) WM_PAINT 消息

当窗口的大小，位置，显示内容等发生改变时，窗口就需要重绘。在窗口需要重绘的时候就会响应 WM_PAINT 消息，WM_PAINT 消息的定义为 #define WM_PAINT 0x000F，

(3) WM_DESTROY 消息

在关闭窗口时调用 DestoryWindow 函数，该函数会向窗口发送 WM_DESTROY 消息，在响应该消息时调用 PostQuitMessage 函数，该函数会向消息队列中添加一个 WM_QUIT 消息，当 GetMessage 函数取到该消息时，GetMessage 函数返回 FALSE，消息循环结束。

在程序中调用 UpdateWindow 函数时，会向窗口的消息队列中投递一个 WM_PAINT 消息，该消息意味着要重绘整个窗口，或者重绘窗口的某个部分；

BeginPaint 和 EndPaint 函数的第一个参数都是窗口句柄，第二个参数为指向 PAINTSTRUCT 结构体的指针，PAINTSTRUCT 结构体的定义如下：

BeginPaint(hWnd, &lpPaint) 函数对 lpPaint （PAINTSTRUCT 结构体）主要是填充操作：

  1. lpPaint.hdc：会被设置为一个设备上下文（Device Context，DC）的句柄，这个设备上下文是用于绘制窗口客户区的图形设备接口（GDI）的句柄。通过这个 hdc，可以进行各种绘图操作，例如绘制文本、线条、矩形、圆形等。
  2. lpPaint.fErase：会指示是否需要擦除背景。如果窗口的背景需要被擦除（例如，当窗口大小改变、被覆盖后重新显示等情况），这个成员会被设置为 TRUE，否则为 FALSE。
  3. lpPaint.rcPaint：会被设置为一个 RECT 结构体，该结构体定义了需要重绘的客户区的矩形范围。这个矩形范围是由系统计算得出的，通常是那些由于窗口被部分覆盖、大小变化或其他原因而需要更新的区域。
  4. (AI)lpPaint.fRestore 通常由 Windows 内部使用，它指示是否需要恢复设备上下文的某些状态。一般情况下，在应用程序调用 BeginPaint 时，这个成员的具体值并不需要开发者关心，并且通常为 FALSE。它主要在 Windows 内部进行一些高级的绘制操作和设备上下文管理时使用，开发者在正常的窗口绘制过程中不会直接使用这个成员。
  5. (AI)lpPaint.fIncUpdate 也是 Windows 内部使用的成员，主要用于处理增量更新的情况。在调用 BeginPaint 时，这个成员一般也为 FALSE，表示不是增量更新。如果 Windows 正在进行增量更新操作，它可能会被 Windows 内部的一些机制设置为 TRUE，但这通常不是应用程序开发者需要考虑的部分，因为 Windows 会自动处理这种情况。
  6. (AI)lpPaint.fRestore 和 lpPaint.fIncUpdate 是 Windows 内部使用的成员，对于普通的窗口绘制代码，它们通常会被设置为 FALSE，并且开发者不应该直接修改或依赖它们的值进行正常的窗口绘制操作，而是应该关注 lpPaint.hdc 和 lpPaint.rcPaint 等成员，使用 lpPaint.hdc 进行绘制操作，使用 lpPaint.rcPaint 确定绘制范围。

EndPaint 将结束绘制指定窗口，并释放 BeginPaint 函数分配的资源（设备上下文）；在窗口过程函数中，需要在 BeginPaint 和 EndPaint 之间进行绘制操作，以确保绘制的内容能够正确地显示在窗口上。绘制操作是 WM_PAINT 中最核心的部分。

28. 处理 WM_DESTROY 消息

WM_DESTROY 消息是执行窗口关闭操作时投递的消息

窗口关闭和应用程序退出的区别：窗口关闭，应用程序不一定就退出。应用程序只会在消息循环结束的情况下才会退出，而窗口关闭不一定会导致消息循环结束，特别是一个应用程序拥有多个窗口的情况下。例如，在 Word 、Excel 中可以同时打开多个窗口，而单独的某个文档关闭并不会导致整个应用程序的退出，因此，应用程序中的消息循环也是针对某个特定窗口的，这与应用程序可能拥有多个消息循环类似。

4. Windows 应用程序的基本结构和消息机制

Windows 应用程序是靠消息来驱动的，消息处理的步骤如下：

  1. 单击鼠标，案件或单击按钮时，Windows 操作系统都会将我们的操作打包成一个 MSG 结构体类型的消息对象，并将该消息投递到窗口的消息队列中；
  2. 主函数执行消息循环，从消息队列中取出消息；
  3. 主函数调用 TranslateMessage 函数来转换消息，接着调用 DispatchMessage 函数将消息分派给操作系统，操作系统调用窗口所对应的窗口过程函数来处理消息；
  4. 窗口过程函数处理完消息后返回，其返回值将作为 DispatchMessage 函数的返回值；
