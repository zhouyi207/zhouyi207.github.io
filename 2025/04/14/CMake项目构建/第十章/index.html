第十章：策略和向后兼容

发表于2025-04-14|更新于2025-04-14|CMake 构建实战 项目开发卷
|总字数:1.7k|阅读时长:5分钟|浏览量:

CMake 相当重视向后兼容性，CMake 的策略机制就是为了解决向后兼容问题而产生的。有了策略机制，CMake 可以基本确保基于旧版本 CMake 编写的目录程序可以被新版本的 CMake 配置生成。

1. CMake 策略（以 CMP0115 为例）

CMake 策略的名称以 CMP 开头，后面跟着一个代表策略编号的四位整数，如 CMP0115 就是第 115 号策略。每一个策略都对应着新旧两种不同行为：NEW 行为和 OLD 行为。

借助官方文档查阅 CMake 策略

CMake 官方文档依次列举 CMake 从新到旧的各个版本引入的策略，每个策略都会提供一段摘要以便查阅，以 CMake 3.20 版本引入的 CMP0115 策略，它的摘要是 “源文件扩展名必须显示指定”。

在 CMake 3.19 及以前的版本中，为 add_executable 等命令指定 <源文件> 参数时，可以省略源文件的扩展名，如 add_executable(A main)，CMake 会自动根据项目采用的编程语言尝试为其添加扩展名并查找对应的源文件。然而在 CMake 3.20 及以后的版本中，CMake 要求 <源文件> 参数必须显示指定文件的扩展名，如 add_executable(A main.cpp)。

在这里 OLD 行为允许使用以前的方式，NEW 行为要求必须使用新的方式。

2. 指定 CMake 最低版本要求：cmake_minimum_required

该命令用于指定执行当前 CMake 程序所需 CMake 的 <最低版本>。<最低版本> 参数格式为通用的版本号格式，即 主版本号.次版本号[.补丁版本号[.修订版本号]]，其中主版本号和次版本号是必须的。如果检测到当前 CMake 的版本低于 <最低版本> 的要求，CMake 会报告致命错误，终止执行。

最低版本要求与策略设置

cmake_minimum_required 命令被调用时，除了检测当前 CMake 版本，还会设置当前 CMake 程序的策略行为：<最低版本> 及其之前版本的 CMake 引入的策略将全部被设置为 NEW 行为，而之后版本的 CMake 引入的策略将不会被设置。未被设置的策略默认会采用 OLD 行为，但会同时产生警告信息。

3. 管理策略行为：cmake_policy

cmake_policy 命令有多个子命令，可以分别用于获取和显示指定策略的行为等。

1. 按策略名称设置策略行为

该命令可以设置 <策略名称> 对应的 CMake 策略的行为为 NEW 或 OLD。<策略名称> 即 CMP 加四位数字，如 CMP0001.

2. 获取策略行为

该命令可以将 <策略名称> 对应的 CMake 策略的行为获取到 <结果变量> 中。如果指定的策略未被设置，<结果变量> 会被赋为空值，否则它会被赋值为 NEW 或 OLD。

3. 按 CMake 版本设置策略行为

该命令可以根据指定的 CMake <最低版本> 和 <策略兼容的最高版本> 设置全部已知策略的行为。

<最低版本> 最低不能低于 2.4，最高不能超过当前运行的 CMake 版本号。<策略兼容的最高版本> 最低不能低于 <最低版本>，最高没有限制，可以设置为未来的版本号。

4. 管理 CMake 策略栈

每一个子目录的目录程序，以及 include 和 find_package 引用的模块程序都会创建一个新的策略作用域，并将其追加到策略栈中。当我们使用 cmake_policy 设置策略行为时，实际上只是在修改栈顶的策略行为。

在某个子目录或模块程序中定义的策略行为，不会影响其他子目录或其他模块程序中定义的策略行为，除非指定了 NO_POLICY_SCOPE 参数，那么引用的模块程序不会拥有一个新的策略栈。

这两个命令分别用于当前设置的策略行为入栈和出栈，如果需要对 CMake 程序进行重构升级，这一命令将会非常有帮助。

4. 渐进式重构 CMake 程序

策略能够很好地让 CMake 兼容古老的代码，同时输出警告信息，帮助及时偿还计数债务，重构代码以兼容新版。重构代码通常会采用渐进式重构的方式。当切换到新版本 CMake 后，先不要修改 cmake_minimum_required 中指定的最低版本。

1. 局部代码重构并启用新行为

首先应该对部分 CMake 代码进行重构以采用 NEW 行为，另外新的代码也应直接按照 NEW 行为来编写。过程如下：

随着重构的不断进行，可能某个子目录下的所有目录程序均已完成重构，那么就可以直接调用 cmake_policy(SET <策略名称> NEW) 命令对整个目录程序采用指定策略的 NEW 行为。

2. 禁用警告信息

将对应策略行为显示设置为 OLD 行为，CMake 就不会产生警告信息了。

3. 同时兼容旧版 CMake

if 命令支持判断策略是否存在，借助它可以根据当前 CMake 版本是否存在指定的策略，来进行不同的项目配置。

4. 为全部策略采用新行为

为了给其他用户升级 CMake 版本留下足够的过渡时间，不必急于移除这些 if(POLICY) 条件分支。在这种情况下，可以直接调节 cmake_minimum_required 命令的 <策略兼容的最高版本> 参数来实现新旧版本的同时兼容。

这样一来，使用 CMake 3.19 程序仍然可以正常运行，只不过涉及新版本策略的 if(POLICY) 条件不会成立，会采用 else 分支中的旧版设置。如果使用 CMake 3.20，则会自动地将全部策略设置为 NEW 行为。
