第八章：生成器表达式

发表于2025-04-12|更新于2025-04-12|CMake 构建实战 项目开发卷
|总字数:3.9k|阅读时长:13分钟|浏览量:

CMake 在生成阶段，能够根据具体选用的构建系统生成器生成特定的配置，因此生成器表达式常常用于获取与构建系统相关的信息，如当前构建模式（DEBUG 或 RELEASE 等），构建目标对应的二进制文件名称等。一般来说，这些信息在构建系统生成器之前，也就是在配置阶段时，是无从知晓的。不过也有一些特殊情况，如对于单构建模式的构建系统来说，当前构建模式是在配置阶段由 CMAKE_BUILD_TYPE 变量确定的。不过，生成器表达式对它们同样有效，因此更为通用。

在构建跨平台程序的过程中，可能涉及不同的构建系统，而生成器表达式对它们之间的差异做了很好的封装隐藏，因此不可避免地会用到生成器表达式。生成器表达式大体分为两类：布尔型生成器表达式和字符串生成器表达式。

1. 支持生成器表达式的命令

很多命令支持将生成器表达式作为参数的一部分，基本上只要在生成阶段工作的命令都会对生成器表达式有所支持。

  • string(GENEX_STRIP) 命令用于删除输入字符串中的生成器表达式。事实上，该命令与生成器表达式的解析无关，因为它仅仅是根据语法删除字符串中的生成器表达式。该命令在 CMake 配置阶段执行。
  • file(GENERATE) 命令用于在 CMake 生成阶段为每一个构建模式生成一个指定的文件。其中与输出文件名，文件内容，生成条件，构建目标等相关的参数中均可包含生成器表达式。该命令常用于调试生成器表达式的值。

由于 message 命令在 CMake 配置阶段执行，不能正确解析并输出生成器表达式的值。这也是为什么常用 file(GENERATE) 命令调试生成器表达式的值，而不能使用 message 命令的原因。

2. 布尔型生成器表达式

在生成阶段，布尔型生成器表达式会被解析为 0 或 1。布尔型生成器表达式通常作为分支条件的参数嵌套在字符串生成器表达式中。

表示生成器表达式的语法形式为 “$<生成器表达式>”，其中尖括号是语法的组成部分。因此，在这里介绍生成器表达式中的参数时，使用花括号 {和}。

1. 转换字符串为布尔值：BOOL

该表达式会把 {字符串} 转换为布尔值，如果出现下列情况之一，其值为 0：

  • {字符串} 为空；
  • {字符串} 为假值常量，即 NOTFOUND, IGNORE, OFF, NO, N, FALSE, 0 或以 -NOTFOUND 结尾的字符串（均不区分大小写）；

其他情况下，其值为 1；

2. 逻辑运算

表达式 描述
$<AND:{条件1}[,{条件2}]...> 当所有 {条件} 都为真时，其值为 1，否则为 0
$<OR:{条件1}[,{条件2}]...> 当任一 {条件} 都为真时，其值为 1，否则为 0
$<NOT:{条件}> {条件} 为假时，其值为 1，否则为 0

3. 关系比较

表达式 描述
$<EQUAL:{数值1},{数值2}> 当 数值1 与 数值2 相等时，其值为 1，否则为 0；仅支持比较整数
$<STREQUAL:{字符串1},{字符串2}> 当 字符串1 与 字符串2 相等时，其值为 1，否则为 0；该比较是区分大小写的
$<IN_LIST:{字符串},{列表}> 当 字符串 是 列表 中的一个元素时，其值为 1，否则为 0；字符串的比较是区分大小写的
${VERSION_LESS:{版本号1},{版本号2}} 小于
${VERSION_LESS_EQUAL:{版本号1},{版本号2}} 小于等于
${VERSION_EQUAL:{版本号1},{版本号2}} 等于
${VERSION_GREATER_EQUAL:{版本号1},{版本号2}} 大于等于
${VERSION_GREATER:{版本号1},{版本号2}} 大于

4. 谓词查询

表达式 描述
$<TARGET_EXISTS:{目标}> 当 {目标} 存在时，其值为 1，否则为 0；
$<CONFIG:{构建模式}> 当构建模式为 {构建模式} 时，其值为 1，否则为 0；不区分大小写；
$<PLATFROM_ID:{操作系统1}[,{操作系统2}]...> 当操作系统为 {操作系统} 时，其值为 1，否则为 0；当前操作系统的值即变量 CMAKE_SYSTEM_NAME 的值，一般为 Linux、Windows、Darwin(macOS) 之一
$<{编程语言}_COMPILER_ID:{编译器1}[,{编译器2}]...> 当前指定 {编程语言} 使用的编译器为 {编译器} 之一时，其值为 1，否则为 0；当前编译器的值即变量 CMAKE_<编程语言>_COMPILER_ID 的值
$<{编程语言}_COMPILER_VERSION:{版本号}...> 当前对指定 {编程语言} 使用的编译器的版本号为 {版本号} 时，其值为 1，否则为 0；当前编译器版本号的值即变量 CMAKE_<编程语言>_COMPILER_VERSION 的值
$<COMPILE_FEATURES:{编译特性1}[,{编译特性2}]...> 当前编译器支持的编译特性包含全部指定的 {编译特性} 时，其值为 1，否则为 0
$<COMPILE_LANGUAGE:{编程语言1}[,{编程语言2}]...> 当前编译器的编程语言为 {编程语言} 时，其值为 1，否则为 0
$<COMPILE_LANG_AND_ID:{编程语言}, {编译器1}[,{编译器2}]...> 当前编译器的编程语言为 {编程语言} 且编译器为 {编译器} 时，其值为 1，否则为 0

对于 Visual Studio 和 Xcode 生成器而言，CMake 无法分别对 C 和 C++ 语言的源文件设置不同的宏定义或头文件目录；对于 Visual Studio 生成器而言，甚至不能为 C 和 C++ 语言设置不同的编译选项。在使用这两个生成器时，当目标的源文件中包含 C++ 源文件时，该表达式一律按照编程语言为 CXX 来匹配参数，否则按编程语言为 C 进行匹配。

3. 字符串生成器表达式

字符串生成器表达式在生成阶段会被解析为一段字符串，与布尔值生成器表达式一样，字符串生成器表达式也可以嵌套使用在其他表达式的参数中。

1. 字符转义

2. 条件表达式：IF

3. 字符串变换

分隔符链接：JOIN

该表达式会将 {列表字符串} 中的每一个元素以指定的 {分隔符} 分割并连接在一起

大小写转换：LOWER_CASE、UPPER_CASE

移除重复元素：REMOVE_DUPLICATES

该表达式会将 {列表字符串} 中重复的元素移除，并将最终的列表字符串作为表达式的值。

列表筛选：FILTER

该表达式会将 {列表字符串} 中能够匹配到 {正则表达式} 的元素保留（若指定了 INCLUDE 参数）或移除（若指定了 EXCLUDE 参数），并将最终的列表字符串作为表达式的值。

生成 C 标识符：MAKE_C_IDENTIFIER

该表达式会将 {字符串} 转换为合法的 C 标识符，并作为最终的值。与 string(MAKE_C_IDENTIFIER) 命令一样，它也将非字母或数字的字符转换为下划线。

转换为 Shell 路径：SHELL_PATH

该表达式会将 {绝对路径列表字符串} 中的每一个绝对路径的格式转换为当前 Shell 所需的路径格式。

4. 目标相关表达式

目标名称：TARGET_NAME_IF_EXISTS

当指定 {目标} 存在时，该表达式解析后的值即 {目标} 的名称，否则其值为空字符串。

目标的二进制文件：TARGET_FILE

该表达式解析后的值即 {目标} 构建后生成的二进制文件的绝对路径。

表达式 描述 示例
$<TARGET_FILE:{目标}> 返回 {目标} 的二进制文件的绝对路径 /a/libbase.so
$<TARGET_FILE_BASE_NAME:{目标}> 返回 {目标} 的二进制文件的基本名称 /base
$<TARGET_FILE_DIR:{目标}> 返回 {目标} 的二进制文件所在的目录 /a
$<TARGET_FILE_NAME:{目标}> 返回 {目标} 的二进制文件的文件名 libbase.so
$<TARGET_FILE_PREFIX:{目标}> 返回 {目标} 的二进制文件的前缀 lib
$<TARGET_FILE_SUFFIX:{目标}> 返回 {目标} 的二进制文件的后缀 .so

目标的链接文件：TARGET_LINKER_FILE

该表达式解析后的值即链接 {目标} 时所需文件的绝对路径。

表达式 描述 示例
$<TARGET_LINKER_FILE:{目标}> 返回链接 {目标} 时所需文件的绝对路径 /a/libbase.so
$<TARGET_LINKER_FILE_BASE_NAME:{目标}> 返回链接 {目标} 时所需文件的基本名称 /base
$<TARGET_LINKER_FILE_DIR:{目标}> 返回链接 {目标} 时所需文件所在的目录 /a
$<TARGET_LINKER_FILE_NAME:{目标}> 返回链接 {目标} 时所需文件的文件名 libbase.so
$<TARGET_LINKER_FILE_PREFIX:{目标}> 返回链接 {目标} 时所需文件的前缀 lib
$<TARGET_LINKER_FILE_SUFFIX:{目标}> 返回链接 {目标} 时所需文件的后缀 .so

目标的带 SONAME 的文件：TARGET_SONAME_FILE

该表达式解析后的值即 {目标} 对应的带 SONAME 的文件（如扩展名为 .so.l 的文件）的绝对路径。{目标} 参数必须是一个动态库目标的名称。

该表达式仅拥有下面两个变种以获取路径的不同部分：

表达式 描述 示例
$<TARGET_LINKER_FILE_DIR:{目标}> 返回链接 {目标} 时所需文件所在的目录 /a
$<TARGET_LINKER_FILE_NAME:{目标}> 返回链接 {目标} 时所需文件的文件名 libbase.so

目标的 PDB 文件：TARGET_PDB_FILE

该表达式解析后的值即 {目标} 对应的 .pdb 符号文件的绝对路径。该表达式仅适用于 MSVC 编译器，因此往往在 if(MSVC) 的条件分支中使用。

表达式 描述 示例
$<TARGET_PDB_FILE:{目标}> {目标} 对应的 Bundle 目录的绝对路径 /a/libbase.so
$<TARGET_PDB_FILE_BASE_NAME:{目标}> {目标} 对应的 Bundle 目录的基本名称 /base
$<TARGET_PDB_FILE_DIR:{目标}> {目标} 对应的 Bundle 目录所在的目录 /a
$<TARGET_PDB_FILE_NAME:{目标}> {目标} 对应的 Bundle 目录的文件名 libbase.so
$<TARGET_PDB_FILE_PREFIX:{目标}> {目标} 对应的 Bundle 目录的前缀 lib
$<TARGET_PDB_FILE_SUFFIX:{目标}> {目标} 对应的 Bundle 目录的后缀 .so

目标的 Bundle 文件：TARGET_BUNDLE_DIR

该表达式解析后的值即 {目标} 对应的 Bundle 目录的绝对路径。{目标} 参数必须是一个 Bundle 目标（具有 MACOSX_BUNDLE 属性的可执行文件目标或具有 FRAMEWORK 或 BUNDLE 属性的库目标）的名称。

如果想获取目标 Bundle 内容中的目录路径，可以用下面这个表达式：

目标属性：TARGET_PROPERTY

这两个表达式可用于获取构建目标的 {目标属性}，属性值会作为表达式最终的值。其中，第一个表达式可以指定 {目标} 参数，而第二个表达式则会根据所在上下文来确定用于获取属性的目标。

目标的目标文件：TARGET_OBJECTS

该表达式解析后的值即 {目标} 对应的目标文件的列表。{目标} 参数必须是一个目标文件库目标的名称。

5. 解析生成器表达式

解析一般表达式：GENEX_EVAL

该表达式会将指定的 {生成器表达式} 参数在当前上下文中解析为具体的值，并作为该表达式的值。一般来说，这种用例通常出现在构建目标的自定义目录属性中。

解析目标相关表达式：TARGET_GENEX_EVAL

有时需要在构建目标的上下文中解析生成器表达式。例如，要解析的 {生成器表达式} 中包含 $<TARGET_PROPERTY:{属性}> 表达式时，可以使用 TARGET_GENEX_EVAL 表达式。该表达式会将指定的 {生成器表达式} 参数在 {构建目标} 的上下文中解析为具体的值，并作为该表达式的值。

第十章：策略和向后兼容
